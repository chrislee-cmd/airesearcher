# CONTEXT-FOR-CD — 체인 레인 "요약 카드 + 우측 인스펙터" 모델 (시안 의뢰)

_2026-10-12 · writer → CD · **사용자 지시 기반 신규 방향**. 1차 요청 = **시안(장면)만** — 풀 번들은 사용자 확정 후._

---

## 0. 사용자 원문 (요지 아닌 원문 — 뉘앙스 보존)

> "체인에 위젯을 넣게 되면, 지금같은 위젯 뷰에서 세팅값들을 설정하는게 아니었으면 좋겠어. **너무 보기가 안좋아.**
> 오히려, 체인에 위젯을 넣고, **체인 안에 위젯을 클릭하면 오른쪽 사이드바가 열려서, 세부 세팅을 하도록** 해줘.
> 그리고 **체인안에 있는 위젯은 설정된 결과값만 정리해서 보여주는 정도로만** 기능했으면 좋겠어."

---

## 1. 지금 무엇이 문제인가 (CD 가 봐야 할 현상)

현재 레인에 도킹된 위젯은 **독립 실행될 때의 카드를 그대로** 씁니다 — `604 × 900`, 내부에 셋업 아코디언·입력 필드·옵션 카드·실행 버튼이 전부 들어 있습니다. 그래서 체인이 길어지면 화면이 **"설정 폼 여러 장을 가로로 늘어놓은 것"** 이 됩니다. 캔버스 기본 줌이 0.3~0.45 라 그 폼들은 **읽히지도 않는 크기**로 늘어서 있고, 읽으려면 줌인해야 하는데 줌인하면 체인 전체가 안 보입니다.

**즉 지금 구조는 "전경(파이프라인)과 세부(설정)를 같은 평면에 놓아 둘 다 실패"하고 있습니다.** 사용자 표현 "너무 보기가 안좋아"의 실체가 이것입니다.

---

## 2. 가고자 하는 모델 — 3면 분업

```
┌─ 팔레트 240 ─┬────────── 작업면(체인 레인) ──────────┬─ 인스펙터 ─┐
│  위젯 목록    │  [요약카드]─[세그먼트]─[요약카드]─…    │  선택된    │
│  (조립 소스)  │                                       │  위젯의    │
│              │  ← 카드는 "무엇이 어떻게 설정됐나"만    │  세부 설정 │
└──────────────┴───────────────────────────────────────┴───────────┘
     조립                    전경(읽기)                    편집
```

- **레인 카드 = 읽기 전용 요약.** 설정된 값만 정리해 보여줍니다. 입력 필드·토글·실행 버튼 **없음**.
- **우측 인스펙터 = 편집.** 레인 카드를 클릭하면 열리고, 그 위젯의 세부 설정이 여기 들어갑니다.
- **팔레트(좌)는 그대로** — 조립 소스 + 현재 상태판. 이번 변경 범위 아님.

**이 분업의 요점**: 체인을 볼 때는 **"어떤 단계가 어떻게 설정됐는지"가 한 화면에** 들어오고, 고칠 때만 오른쪽이 열립니다. 전경과 세부가 **다른 평면**에 놓입니다.

## 3. CD 에 요청하는 시안 (장면)

**장면 I0 — 레인 전경 (인스펙터 닫힘)**
요약 카드 3~4장이 가로로 늘어선 상태. 각 카드가 **설정 요약**만 담고 있을 때 체인 전체가 어떻게 읽히는지. 이 장면이 이번 변경의 성패를 결정합니다.

**장면 I1 — 요약 카드 단독 (상태 변주)**
한 장을 확대해, 아래 4경우를 각각:
- **미설정** (방금 끼워 넣음 — 설정 필요)
- **설정 완료** (실행 전)
- **실행 중**
- **완료 — 산출물 있음**

**장면 I2 — 인스펙터 열림**
카드 클릭 → 우측 패널 열린 상태. 선택된 카드가 레인에서 어떻게 표시되는지(선택 표시)도 함께.

**장면 I3 — 인스펙터 내부**
세부 설정이 들어찬 상태. 섹션 구분·입력 밀도·하단 액션(저장/되돌리기가 필요한지 포함).

**장면 I4 — 좁은 화면**
팔레트 + 레인 + 인스펙터 3면이 동시에 들어가지 않는 폭일 때의 처리.

## 4. CD 가 판단해 줄 열린 질문

**Q1. 요약 카드의 크기와 형태.**
현재 604×900 은 "설정 폼이 들어가야 해서" 나온 값입니다. 요약만 담으면 **훨씬 작아질 수 있고, 작아져야 할 것**으로 봅니다(그래야 체인 전체가 기본 줌에서 읽힘). 세로로 긴 카드 / 가로로 넓은 낮은 카드 / 정사각 타일 중 무엇이 맞는지, 그리고 **그 안에 요약을 몇 줄까지** 담을지.
→ writer 관찰: 카드가 작아지면 **줌 자체가 거의 불필요**해질 수 있습니다. 그게 더 나은 방향이면 그렇게 제안해 주세요(줌 퇴역은 후속 결정).

**Q2. "설정 결과 요약"에 무엇을 담는가.**
위젯마다 설정 항목이 다릅니다(파일 n개 / 질문 n개 / 페르소나 n명 / 모델·언어·옵션 …). 공통 형식이 필요합니다 — 예: `레이블 : 값` 행의 나열인지, 칩 묶음인지, 2~3개만 보이고 "외 n개"로 접는지. **담을 수 있는 최대 줄 수**를 정해 주시면 writer 가 위젯별 요약 규칙을 거기에 맞춰 정의합니다.

**Q3. 미설정 상태를 어떻게 말하는가.**
끼워 넣자마자는 아무것도 설정되지 않았습니다. 카드가 "설정이 필요하다"를 어떻게 말하는지(점선? 안내 문구? CTA 버튼?), 그리고 **그 상태에서 체인을 실행하려 하면** 어떻게 막는지(§5 세그먼트 차단 표현과 연결).

**Q4. 인스펙터의 폭·열림 방식·닫힘.**
오버레이(레인 위에 덮음) vs 밀어내기(레인이 좁아짐) vs 고정 3분할. 폭. 닫기 수단. **선택된 카드와 인스펙터의 시각적 연결**(선택 링? 커넥터?)을 어떻게 만들지.
→ writer 관찰: 레인이 가로 스크롤 평면이라 **오버레이면 선택 카드가 가려질 위험**이 있습니다. 밀어내기면 레인 좌표가 흔들립니다. 이 트레이드오프를 CD 가 판정해 주세요.

**Q5. 인스펙터 안의 설정 UI 를 새로 그리는가, 기존 셋업 UI 를 옮기는가.**
기존 위젯 셋업 아코디언을 그대로 옮기면 빠르지만 **좁은 패널에 맞지 않습니다**(가로 604 전제로 그려짐). 패널 폭에 맞는 **새 설정 레이아웃**이 필요하면 그 형식(섹션 헤더·라벨 위치·입력 폭·간격)을 정해 주세요.

**Q6. 산출물은 어디에 있는가.**
실행이 끝나면 결과물(전사록·분석표·보고서)이 생깁니다. 요약 카드에 **"결과 보기" 진입점**만 두고 실제 결과는 기존 풀뷰로 여는 게 맞는지, 아니면 인스펙터에 결과 탭을 두는지.

## 5. 불변 제약 (재설계 금지 — 이번 범위 밖)

1. **레인의 선형 구조·세그먼트 문법 불변.** 카드 사이 세그먼트(연결선 96↔464, 반반 선 차단 표현, 흐름 애니메이션, 화살촉 7/11px)와 캡슐(400px, 승인/실패/보류)은 **그대로**입니다. 바뀌는 것은 **카드의 내용물과 크기**이지 체인 문법이 아닙니다.
2. **팔레트(240/72)·타일(216×64)·12상태·드래그 조립 규칙 불변.**
3. **Soft Identity 토큰 체계 전부 유효** — 색/선/그림자 4단/radius/타이포 스케일은 `soft-identity/README.md` 그대로. 새 색이 필요하면 `proposed-token:` 으로.
4. **상태 어휘 불변** — 노드 7상태·세그먼트 7종·신호 5톤·맥동은 running 에만.
5. **기존 풀뷰(1400×840 기준치)는 유지** — 체인 밖에서 위젯을 단독으로 쓰는 경로는 그대로입니다. 이번 변경은 **"체인 안에 있을 때"** 만 바꿉니다.

## 6. 사실 자료 (CD 가 현황을 재질의하지 않도록)

- **현재 레인 카드**: 604×900, radius 20, 1px `--line`, `--sh-card`. 내부에 셋업 아코디언 + 상태 footer + 산출물 영역.
- **레인 프레임**: 헤더 72px(아이콘 40×40 + 제목 22px + 모드 세그먼트 + 상태 텍스트 18px mono + 비용 칩), 본문 `padding 32/40`, 가로 스크롤.
- **작업면**: 배경 #f7f7f8 + 1px 점 22px 간격, 줌 0.3~1.0 연속, 기본 fit 은 2카드 기준 0.3~0.45.
- **위젯 수**: 캔버스 노출 9종 / 실사용 7종(2종은 출시 전 게이트).
- **체인 호환성**: 아무 위젯이나 아무 순서로 붙지 않습니다 — 정적 호환 그래프가 있고, 불가 조합은 드롭 자체가 거절됩니다. 요약 카드에 **순서 제약을 드러낼 필요는 없습니다**(드롭 시점에 이미 거름).
- **구조 상세 전체**: `canvas-modular/full/README.md` · `soft-identity/README.md` · `widget-chain/v3/` 참조. 치수 SSOT 는 여전히 canvas-modular/full + v3.

## 7. 진행 방식

**1차 = 시안(장면 I0~I4)만.** 사용자가 장면을 보고 확정한 뒤에야 풀 번들(BUILD-SPEC·`.dc.html`·GEOMETRY)을 요청합니다. 이 순서는 지난 체인 작업에서 **피벗 2회를 겪고 세운 것**이고, 캔버스 모듈화 때 장면 선확인으로 피벗 0회를 달성했습니다.

답신은 이 디렉토리 관례대로 번들(또는 장면 md + `.dc.html`)로 주시면 writer 가 스펙으로 전개합니다.
