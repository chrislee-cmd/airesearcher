## 0. 선행 조건 — 리브랜드 1단계 머지 후 시작 (확정)
> **이 번들은 Soft Identity 리브랜드 1단계가 main 에 머지된 뒤 시작합니다.** (사용자 확정 2026-10-12)

이 번들의 색·선·그림자는 **Soft Identity** 값입니다. 리브랜드 패키지는 `design_handoff_soft_identity/`(README · `tokens.css`)이고, **1단계**는 그 README "작업 순서 권장"의 1–2번입니다:
1. `tokens.css` 를 `globals.css` 에 등재하고 Tailwind 에 매핑
2. 공유 셸 교체 — `WidgetShell` → `FullviewShell`(사이드바 포함) → 리스트 표면 셸 → 모달/팝오버/Picker

**순서:** 리브랜드 1단계 PR 머지 → **이 번들(Phase 1) 시작** → 리브랜드 3–6단계(위젯 본문 · 보고서 블록 · 공개 표면 · Memphis 토큰 삭제)는 이 번들과 병행해도 되고 뒤에 해도 됩니다.

**두 작업을 한 PR 로 묶지 마세요.** 시각 회귀와 드래그 동작 결함이 섞이면 원인을 가를 수 없습니다(LEARNINGS §8 — 결함 대부분이 실조작 프리뷰에서만 드러남).

**1단계 완료 확인(시작 전 체크):** `globals.css` 에 `--tint-*` · `--sh-card` · `--r-panel` 이 있고, 위젯 카드·풀뷰 프레임이 1px 선 + 옅은 그림자로 렌더되면 시작해도 됩니다. 레인 카드는 셸을 쓰므로 그 시점에 이미 Soft 로 보입니다 — 레인 **chrome**(헤더·슬롯·세그먼트)만 이 번들 §5 값으로 맞추면 됩니다.

**구조·치수·상호작용은 리브랜드와 무관합니다.** 리브랜드가 바꾸는 것은 시각 값뿐입니다.

## 1. 바뀌는 것 / 안 바뀌는 것
- **새로 만듭니다:** 팔레트(펼침 240 / 접힘 72) · 팔레트 타일과 그 상태들 · 작업 목록 펼침 · 팔레트 → 레인 드래그 · 전환 온보딩.
- **없앱니다:** 그리드 캔버스(3×3 셀 배치) · 위젯 내비게이터. 내비게이터는 이 번들과 **같은 PR**에서 제거합니다. 과도기 동안 두 개를 같이 두면 상태가 이중으로 표시됩니다.
- **안 바뀝니다:** 레인 내부(v3) · `ChainView` 계약 · 위젯 셸 · 풀뷰.
- **토큰:** 신규 토큰은 `--palette-w: 240px` · `--palette-tile-h: 64px` 두 개뿐입니다(writer 접수).

## 2. 규칙
1. **제스처는 뜻이 하나씩입니다.** 끌기 = 체인에 조립, 누르기 = "그 위젯이 있는 곳으로". Phase 2에서도 뜻이 바뀌지 않습니다.
2. **팔레트는 공급원입니다.** 끌어가도 타일이 자리에서 빠지지 않고, 순서·개수도 바뀌지 않습니다.
3. **작업면에는 꺼낸 것만 둡니다.** 체인 밖에서 실행 중인 위젯은 팔레트 타일로만 보이고, 작업면에는 아무것도 그리지 않습니다(P3c).
4. **미지원 위젯을 흐리게 하지 않습니다.** 체인을 지원하는 위젯에만 "체인" 칩을 붙입니다.
5. **로스터는 발행 SSOT에서 읽습니다**(`CANVAS_ORDER` × `widget_visibility`). 9종을 하드코딩하지 않고, 톤·크레딧은 FEATURES 메타를 씁니다. 미발행 위젯은 목록에서 뺍니다.
6. **좌표 판정은 기하로만 합니다.** hover, 드롭 대상, 노출 여부는 모두 포인터 좌표 대 rect로 판정하고 enter/leave 이벤트는 쓰지 않습니다(LEARNINGS §2-2). hover로 나타나는 컨트롤은 mount를 토글하지 말고 가시성만 토글합니다(§2-3).

## 5. 드래그 (P2)
| 단계 | 규칙 |
|---|---|
| 시작 | pointerdown 후 4px 이상 움직이면 드래그로 확정합니다. 그 전에 떼면 누르기입니다. 타일 전체가 손잡이이고, chain 상태 타일은 끌 수 없습니다 |
| 고스트 | 216×64 사본을 **body 포털**(`z-overlay`)에 그립니다. 화면 px 고정이라 줌과 무관하고, rotate 2° · 그림자 `0 12px 32px ink/16` · 집은 지점 오프셋을 유지합니다 |
| 후보 표시 | 받을 수 있는 빈 슬롯만 "자리" 상태(1.5 dashed `--faint`, ↓)로 바꿉니다. 팔레트에서는 fit 상태를 드래그 시작 전 hover 때 미리 보여줍니다 |
| 판정 | **포인터 clientX/Y ∈ 슬롯.getBoundingClientRect()** 하나로만 판정합니다. 두 좌표계(팔레트 = 화면, 슬롯 = 캔버스 transform 안)를 건너지만 rect가 이미 화면 좌표라 환산이 필요 없습니다. pointermove는 rAF로 스로틀합니다 |
| 가드 | `registry.ts`의 `CHAIN_COMPAT_EDGES` · `validateSteps`를 UI가 직접 호출합니다. 서버 POST가 같은 함수로 재검증합니다(LEARNINGS §4) |
| 수용/거절 외형 | v3 L1 / L2 / L2b 문법 그대로, 바탕만 Soft 값(수용 = 들어올 위젯 틴트 + 1.5 dashed ink, 거절 = `--err-bg` + 1.5 dashed `--err-dot`). 고스트 옆에 라벨("2단계" ink pill / "놓을 수 없음" err) |
| 저줌 | FOCUS_THRESHOLD(0.55) 미만에서는 click-to-focus 오버레이가 레인을 덮습니다. **드래그 중에만** 그 오버레이에 `pointer-events: none`을 줍니다(§2-1, §8-8) |
| 드롭 | 고스트를 즉시 제거합니다(날아가는 보간 없음). 슬롯 opacity 1→0, 카드 0→1을 동시에 160ms ease-out으로 바꾸고, 남은 단계가 있으면 다음 빈 슬롯을 만듭니다. 타일은 chain 상태가 됩니다 |
| 낙관적 반영 | POST 전에 화면을 먼저 바꿉니다. 서버가 거부하면 카드를 160ms에 걸쳐 슬롯으로 되돌리고 토스트로 사유를 알립니다 |
| 취소 | Esc · 슬롯 밖(빈 작업면 포함) · 거절 슬롯 · 팔레트 위. 고스트가 원본 위치로 200ms ease-in-out 이동한 뒤 사라집니다. 빈 작업면에 놓아 취소된 경우에만 "체인 자리에 놓아야 들어가요" 라벨을 1.6s 보여줍니다. Phase 1에서는 빈 작업면에 놓아도 아무것도 만들지 않습니다 |
| 키보드 | 포커스 → Space로 들어올림(lifted). 고스트 없이 ←→로 슬롯 사이를 이동합니다(거절 슬롯도 들르되 reject로 표시하고 사유를 읽음). Space/Enter로 놓으면 포커스가 새 카드로, Esc로 취소하면 포커스가 원본 타일로 갑니다. 단계마다 `aria-live="polite"`로 안내합니다 |
| reduced-motion | 크로스페이드·복귀 이동 없이 즉시 바꿉니다 |

**portal 함정(§8-2):** 고스트는 이벤트를 받지 않습니다(`pointer-events: none`). 판정은 document 레벨 pointermove/pointerup에서 기하로 하므로, 카드 포털의 합성 이벤트 버블 문제를 겪지 않습니다. 레인 슬롯 위에 이미 포털된 카드가 있어도 마찬가지입니다.

## 6. 누르기와 복수 실행 (P1 · P5)
- **위치(location)** = 위젯이 지금 일을 갖고 있는 곳입니다. 레인 카드(체인 소속이면 1개, 대기여도 포함)와 끝나지 않은 풀뷰 실행(running · awaiting · paused · error)이 위치입니다. 완료된 실행은 위치가 아닙니다.
- **누르기 규칙:** 위치 0개 → 새 풀뷰를 엽니다. 1개 → 그 위치로 갑니다(레인 카드면 팬 240ms + 링 1.2s + 포커스 이동, 풀뷰면 그 풀뷰). 2개 이상 → 작업 목록을 펼칩니다. 시스템이 대신 고르지 않습니다.
- **둘째 줄 우선순위:** 실패 > 멈춤 > 승인 대기 > 진행 중 > 대기(체인) > 완료(확인 전 1회). 위치가 2개 이상이면 문구 앞에 개수를 붙입니다("2건 · 승인 대기").
- **완료 표시:** 체인 밖 실행이 끝나면 둘째 줄이 1회 "완료" 배지가 되고, 사용자가 그 풀뷰를 한 번 열면 메타로 돌아갑니다.

## 7. 잔여 화면 (P3)
- **P3a 빈 작업면:** 빈 상태 카드(540, 1px `--line`, radius 16) + 툴바 "+ 새 체인". 요약 pill이 없고, 옛 그리드 자리표시도 그리지 않습니다.
- **P3b 레인만 있음:** 요약 pill은 **실행이 시작된 뒤에만** 띄웁니다(§8-7). "+ 새 체인"은 잠그고(`--fill` / `--faint`) 안내를 한 줄 둡니다. 잠금은 서버 체인 행에서 렌더 중 파생합니다(§9).
- **P3c 레인 밖 실행:** 팔레트 타일로만 보이고 작업면에는 그리지 않습니다.
- **배치:** 툴바는 화면 고정(캔버스 영역 기준 left 24 · top 20, 높이 36), 레인은 캔버스 안(top 78). 내비게이터가 사라지므로 좌상단 겹침(§8-7)이 없어집니다.

## 8. 전환 온보딩 (P4)
- **대상:** 그리드 캔버스를 쓴 적 있는 사용자의 첫 진입 1회. 신규 사용자에게는 보이지 않습니다.
- **형태:** 팔레트를 가리키는 말풍선 하나(340 · ink 면 · radius 14 · `--sh-popover`). 배경을 어둡게 하지 않고, 조작을 막지 않고, 단계 넘김도 없습니다.
- **닫힘:** "알겠어요" · Esc · 팔레트 타일을 처음 누르거나 끌 때. 어느 쪽이든 **사용자 단위 서버 플래그**를 기록하고, 기기가 바뀌어도 다시 띄우지 않습니다.
- **문구:** "위젯은 이제 왼쪽 목록에 있어요" / "캔버스에 모두 펼쳐 두지 않고, 쓸 때만 꺼냅니다. 누르면 열리고, 끌면 체인에 들어갑니다. 만들었던 결과는 그대로 있어요."

## 9. cascade · 레이어 (LEARNINGS §5, §3-2)
- 팔레트는 캔버스 바깥(`[data-canvas]` 형제)에 둡니다. `[data-canvas-body]` cascade가 닿지 않으므로 native button 함정이나 `.text-xl` 함정이 없습니다.
- 고스트와 접힘 팝오버는 body 포털 `z-overlay`. 툴팁도 같습니다.
- 레인 카드 하이라이트 링(P1b)은 포털된 카드 노드에 줍니다. 그리드 래퍼에 주면 안 됩니다(§8-3).
