# Handoff: 위젯 체인 UI v3 — 도킹 레인

## Overview
체인은 캔버스 위의 **레인(선반)**입니다. 처음에는 비어 있고, 사용자가 **카드 본체**를 끌어넣어 체인을 만듭니다. 도킹된 카드에서 평소처럼 작업하고, 레인을 해체하면 카드는 원래 자리로 돌아갑니다.
- 인풋: 레포 `design-handoff/widget-chain/CONTEXT-FOR-CD-V3.md`(사용자가 고른 모델 A, 도킹 레인)
- **그대로 쓰는 것:** `ChainView` 계약, 모드 2종(단계별 승인 기본 / 자동), 크레딧 사전 고지, `ChainChip`, v2 상태 문법(세그먼트·캡슐·산출물 노드). v2 값의 SSOT는 `v2/README.md`입니다.
- **없애는 것:** v2의 출력 포트 핸들, 진입 팝오버, 거터 레인 엣지 경로.

## About the Design Files
`widget-chain-v3.dc.html`은 HTML로 만든 **디자인 레퍼런스**이고 프로덕션 코드가 아닙니다. airesearcher 레포(Next.js + React + Tailwind, `globals.css` 토큰)의 기존 패턴으로 다시 구현하세요. 컴프를 열려면 같은 폴더의 `support.js`가 필요하지만, `support.js`는 옮길 대상이 아닙니다. **장면은 실치수(카드 604×900)로 그린 뒤 50%로 축소해서 보여줍니다.** 아래 수치는 모두 실치수입니다.

## Fidelity
High-fidelity입니다. 카드 **본문**은 회색 블록으로 대신 그렸으니 각 위젯의 실제 본문을 쓰면 됩니다. 새로 만드는 것은 **레인 · 슬롯 · 레인 세그먼트 · 툴바 버튼**이고, 캡슐과 산출물 노드는 v2 값을 그대로 씁니다. 위젯 셸은 바꾸지 않습니다.

## CD 결정 (브리프 §3, §4)
1. **레인 안 카드는 실치수 604×900입니다.** 축소하지 않습니다. 레인 본문이 화면보다 길어지면 레인 본문만 가로로 스크롤됩니다.
2. **진입점은 캔버스 툴바의 "+ 새 체인" 하나입니다.** 카드를 겹치면 자동으로 생성하는 방식은 카드를 옮기다 실수로 체인이 생기므로 쓰지 않습니다. 빈 공간 인터랙션은 발견하기 어려워서 쓰지 않습니다.
3. **도킹은 헤더를 끌어서 합니다.** 언도킹은 **양 끝에서만** 됩니다. **순서 바꾸기는 없습니다**(파일럿 호환 그래프가 일직선이라 순서가 데이터로 정해집니다).
4. **받을 수 없는 드롭이어도 드래그는 시작됩니다.** 레인 위에 올라오면 슬롯이 붉은 점선으로 바뀌고 사유를 보여줍니다. 그대로 놓으면 카드는 원래 자리로 돌아갑니다.
5. **레인은 캔버스 맨 위의 고정 행입니다**(이동할 수 없음). 카드가 빠진 자리는 캔버스가 메웁니다. 카드의 원래 순서를 저장해 두었다가 해체할 때 그 자리로 되돌립니다.
6. **파일럿에서는 레인을 1개만 둡니다.** 레인이 있으면 "+ 새 체인"이 잠기고 옆에 이유가 표시됩니다. **요약 pill은 툴바에 남겨** 레인이 화면 밖일 때 상태를 알려줍니다.

## Geometry (실치수)
- **툴바:** 캔버스 좌상단 (32, 32) · 높이 88 · sticky. "+ 새 체인" pill: 높이 56 · border 2 ink · 20/800 · shadow `3px 3px 0 #1d1b20`. 누른 상태 = ink 채움, 잠김 = bg `#eceef1` · 글자 `#8a8693` · 그림자 없음.
- **요약 pill:** 버튼 오른쪽 · 높이 56 · border 2 ink · 타일 38 원 + "체인 1" 19/800 + 구분선 + 상태(mono 18/800, 상태 색). 클릭하면 레인으로 스크롤합니다.
- **레인:** 캔버스 (32, 152) · 폭은 내용에 맞춤 · border 3 ink · radius 20 · bg `#f7f7f5` · shadow `3px 3px 0 rgba(29,27,32,.14)`.
  - 헤더: 높이 72 · 흰색 · border-b 2 ink · pad 0/24 · gap 16. 순서: 타일 40(radius 11) → "체인 1"(Outfit 24/800) → 모드 세그먼트(조립 중) 또는 모드 배지(실행 후) → 구분선 2×30 → 상태 텍스트(mono 18/800) → 빈 공간 → [잠금 문구] [비용 칩] [액션 텍스트 버튼].
  - 본문: pad 40/32 · 가로 flex · align center.
- **슬롯:** 604×900 · radius 20. 상태별 값:
  - empty: 2.5 dashed `#c9ccd2` · bg `#fbfbf9` · 타일 80(점선, "+") · "위젯을 끌어다 놓으세요" 22/800 · 받을 수 있는 위젯 칩
  - valid: 3 solid ink · bg = 끌려오는 카드 톤 · "↓"
  - invalid: 3 dashed `#ef4444` · bg `#fdf0f0` · ✕ · 사유 22/800 `#b4443f` · 순서 칩(P → T → I)
- **세그먼트:** 기본 폭 96 · 선은 카드 세로 중앙(y=450) · 화살촉(밑변 14, 높이 11). 캡슐이 들어가면 폭 464(캡슐 400 + 좌우 32), 240ms ease-out으로 벌어지고 줄어듭니다.
  - done 3 solid ink · pending 3 dashed `#c9ccd2` · awaiting 3 dashed `#e0a83a` · running = 5px 바탕 `#d6c7f5` 위에 `#8b5cf6` 16/28 반복, `background-position` 0 → 44px, 1s linear · paused/error = 반씩 나눠서 앞쪽 amber/red 실선, 뒤쪽 pending.
  - 라벨(running): 선 위 중앙 · `#f6f2ff`/`#d6c7f5`/`#6b4aa0` · 13/800.
- **캡슐:** v2 값과 같습니다(폭 400 · border 2 상태색 · radius 12 · `shadow-popover`). 세그먼트 안 세로 중앙에 놓고, eyebrow 앞에 24 원 글리프(? / Ⅱ / ✕ / ✓)를 둡니다.
- **산출물 노드:** 320×220 · 레인 마지막 · pending/done 값은 v2와 같습니다(크기만 실치수로 키움).
- **드래그 고스트:** 카드 그대로 · rotate 2deg · shadow `12px 12px 0 rgba(29,27,32,.3)` · 커서 옆 라벨 pill(받을 수 있음 = ink "체인 n단계" / 없음 = `#fdf0f0` "놓을 수 없음").
- **원래 자리 윤곽:** 드래그 중에만 · 2.5 dashed `#c9ccd2` · "원래 자리" 18/700 `#a3a7ad`.

## Interactions
- **드래그 시작:** 카드 헤더(기존 캔버스 카드 이동 제스처). 레인 위에 있을 때만 슬롯 피드백이 나타나고, 레인 밖에 놓으면 평소처럼 카드 이동입니다.
- **판정:** `canDock(feature, position)` = 백엔드 호환 그래프의 엣지가 있는가. 받을 수 있는 위치는 **끝(append)**과, 앞 단계 위젯이면 **처음(prepend)**뿐입니다.
- **언도킹:** 양 끝 카드만 됩니다. 가운데 카드를 끌면 그 슬롯 자리에 invalid 형태를 띄우고 "가운데 단계는 뺄 수 없어요 — 끝에서부터 빼세요"를 표시합니다.
- **잠금:** `status ∈ {running, awaiting_approval, paused_insufficient_credits}`이면 도킹과 언도킹을 모두 막고, 헤더에 잠금 문구를 띄웁니다. error, done, cancelled이면 잠금을 풉니다.
- **해체:** 확인 없이 바로 실행합니다. 카드별로 원래 index로 220ms씩 40ms 간격(stagger)으로 돌아가고, 이어서 레인이 240ms에 걸쳐 사라집니다. 실행 중이면 해체 대신 "체인 종료"(v1/v2와 같음)만 보이고, 종료 후에 해체할 수 있습니다.
- 완료·실패 캡슐을 닫으면 캡슐만 닫히고 **레인은 남습니다**(같은 구성으로 다음 세션을 다시 돌릴 수 있도록).
- `prefers-reduced-motion`: 흐름 애니메이션을 정적 보라 실선으로 바꾸고, 벌어짐·복귀 모션을 즉시 전환으로 바꿉니다.
- 키보드: 카드에 포커스를 두고 `Space`로 들기 → `←/→`로 레인 슬롯 선택 → `Space`로 놓기 / `Esc`로 취소. 받을 수 없는 위치는 aria-live로 사유를 읽어줍니다.

## State
- 원천 데이터: `ChainView`(불변). 추가로 필요한 클라이언트 상태는 `lane: { cards: feature[], originIndex: Record<feature, number> } | null`, `drag: { feature, over: slotIndex | null, valid, reason } | null`입니다.
- 세그먼트 i 종류와 캡슐 위치를 정하는 규칙은 v2 README *State Management*와 같습니다(엣지 = 세그먼트).
- 탑라인은 카드가 아닙니다. `interview_ingest` 카드 다음의 산출물 노드로 그립니다. 칩 번호는 카드 기준(n/3)으로 셉니다.

## 열린 항목
1. **거절 사유 문구의 출처:** 호환 그래프가 "왜 안 되는지"(미지원 / 순서)를 구분해서 돌려줄 수 있는지 확인이 필요합니다. 구분이 안 되면 문구를 "이 위치에는 {위젯}을 넣을 수 없어요" 하나로 통일합니다.
2. **레인 가로 길이:** 카드 3장과 산출물 노드에 캡슐까지 벌어지면 약 2,850px입니다. 레인 본문 가로 스크롤과 캔버스 줌이 함께 동작하는지 확인이 필요합니다.
3. **원래 자리 저장:** 사용자가 레인 밖 카드를 옮긴 뒤 해체하면 index 기준으로 되돌립니다(좌표 기준 아님). 캔버스 배치 모델이 index 기반인지 확인이 필요합니다.
4. v1/v2의 계약 질의(파일 수, 잔액, 환불, 종료 후 status, 프로젝트 목록)는 계속 유효합니다.
