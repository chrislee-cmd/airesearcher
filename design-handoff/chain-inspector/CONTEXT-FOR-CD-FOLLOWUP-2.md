## 1. 신규 질의 ④ — "설정할 것이 0개인 단계"의 시각 처리

### 사실

코드를 파 보니 체인 노드 중 **`interview_ingest`(인터뷰 결과 생성기)는 체인 안에서 사용자가 정할 것이 하나도 없습니다.**

- 입력 = 앞 단계 전사록이 어댑터로 자동 전달(`kickInterviewIngestFromTranscript`).
- 프로젝트 = 체인 레벨 값(`widget_chains.project_id`)이라 단계 설정이 아님.
- 분석 옵션 = API(`convert` → `index`)에 파라미터가 없음.

즉 이 단계의 `requiredFields` 는 **빈 배열**이고, `inspectorSchema` 는 **읽기 전용 행 2개**(앞 단계 전사록 · 프로젝트 문서 n건)만 남습니다.

### 문제

README §1.3 의 4상태(unset · ready · running · done)에는 **"설정할 것이 없어서 처음부터 ready"** 가 들어갈 자리가 없습니다. 그대로 두면 모순이 생깁니다 — unset 카드의 주 버튼은 "설정하기"인데, 눌러도 **편집 가능한 필드가 0개인 패널**이 열립니다.

### writer 가 임시로 정한 것 (구현에 이미 반영, 변경 가능)

`requiredFields` 가 빈 배열이면:

1. **unset 을 건너뛰고 처음부터 ready** 로 렌더.
2. 푸터 액션은 "편집" 대신 **"입력 보기"** — 인스펙터를 열지만 읽기 전용 행만 들어 있음.
3. **"설정하기" 주 버튼은 그리지 않음** (누를 것이 없는 버튼을 두지 않는다).
4. 인스펙터 하단 진행도는 "필수 0 / 0" 대신 **"설정 없음"**(ok 톤), 섹션 자리에 한 줄: "이 단계는 앞 단계 결과를 그대로 분석해서 따로 설정할 것이 없어요."

### CD 에 묻는 것

위 처리가 **4상태 문법과 어긋나지 않는지**, 그리고 **읽히는지**입니다. 생각나는 대안:

- **A (writer 임시안)** — ready 로 시작 + "입력 보기". 상태 어휘를 늘리지 않는 쪽.
- **B** — 5번째 상태 **`auto`** 신설(배지 문구 예: "자동"). 이 단계가 "내가 설정하는 것이 아니라 앞 단계에 매달려 있다"를 **배지로 먼저** 말하는 쪽. 상태 어휘가 늘어나는 비용.
- **C** — ready 유지하되 **푸터 액션 자리를 비워 둠**(클릭 대상은 카드 전체만). 가장 조용하지만, 사용자가 "여긴 눌러도 되나"를 모를 위험.

**답 형식**: 선택 한 줄 + (A/C 면) 카드 1장이면 충분하고, B 면 배지 톤·문구 + I1 갤러리에 한 칸 추가를 부탁드립니다.

> 참고 — 이 질문이 "작은 예외" 처럼 보이지만, 같은 모양이 **반복될 구조**입니다. 체인 노드가 늘어날 때 "앞 단계 산출물만 받아 돌리는 단계"는 계속 생깁니다(현재 노드 4종 중 1종이 이미 그렇고, `topline` 도 설정이 3개뿐입니다). 그래서 일회성 땜질보다 **규칙 한 줄**로 받고 싶습니다.
