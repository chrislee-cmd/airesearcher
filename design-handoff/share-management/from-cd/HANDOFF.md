## 3. 포팅 절차

### 3-1. 먼저 닫아야 하는 것
- **§0.3 열람수 노출** — CD 제안입니다. 사용자가 확정해야 열을 그릴지 정해집니다. 뒤집히면 열람 열(126px)을 지우고 그 폭을 **산출물 열에 줍니다**(`GEOMETRY.md §B1`).
- **§5 contract-change 9건 — 블로킹 없음.** §5-9 는 **`canViewOrgScope: boolean`(응답 최상위)** 으로 확정됐습니다. 남은 것은 값의 유무에 따라 요소를 빼는 판단뿐입니다: §5-1(`resourceLabel`/`tone` 을 계약에 넣을지) · §5-3(`lastViewedAt`) · §5-4(`revokedAt`) · §5-7(철회 알림).
- **§2 proposed-token 5종** 승격. `--shadow-popover` 는 **인터뷰 번들에서도 같은 값으로 요청**했으니 하나로 합치세요.

### 3-2. 셸 — 새로 만들지 마세요
이 표면의 프레임·툴바·열 헤더·행 문법·상태 배지·잠금 트리트먼트는 **`deliverables-library` 에서 그대로 가져온 것**입니다. 라이브러리 컴포넌트를 리스킨하라는 뜻이 아니라, **같은 클래스 조합을 쓰라는 뜻**입니다(`BUILD-SPEC §1.1–§1.4`가 라이브러리 §1과 일치하는지 diff 하세요). 여기서 살짝 다른 값을 쓰면 두 탭을 오갈 때 행 높이가 튑니다.

**탭바는 공유 chrome 입니다.** 브리프는 /library 에 탭 구조가 이미 있다고 했지만 `deliverables-library.dc.html` 헤더에는 탭 행이 없습니다. 없다면 **한 번 만들어 4탭이 함께 쓰고**, 라이브러리 헤더도 같이 손대야 합니다 — 그 작업은 이 번들 범위 밖입니다(`BUILD-SPEC §6-1`).

### 3-3. 상태 3종과 액션
- 배지는 라이브러리 4-상태 문법에서 **3칸만** 씁니다: active=success · expired=속 빈 중립 · revoked=ink 도트 + `surface-disabled`.
- **`error` 틴트를 목록에 쓰지 마세요.** 철회는 고장이 아닙니다. 붉은색은 **철회 버튼과 확인 모달**에만 씁니다.
- **액션 3종은 숨기지 않고 잠깁니다** — 어떤 상태에서도 자리를 지킵니다(`BUILD-SPEC §1.4`). 잠금 = `surface-disabled` + `mute` 라벨 + 그림자 없음. **래퍼 `opacity` 금지.**
- `expired` 에서 **초대 편집만 살아 있습니다** — 기한을 늘려 되살리는 경로입니다.
- `revoked` 행은 **타일의 파스텔을 잃습니다**(`share-shell` 의 "dead end 는 톤을 버린다"와 같은 규칙).

### 3-3b. 스코프 축 (브리프 §9)
**분기는 `canViewOrgScope: boolean`(응답 최상위) 하나로 갑니다.** `issuer: { name, isMine }` 과 조합해 **권한별 3형태**가 나옵니다(`BUILD-SPEC §0.5` · C5).

| `canViewOrgScope` | 선택 스코프 | 토글 | 발급자 필터 | 행 아바타 |
|---|---|---|---|---|
| `false` | — | **렌더 안 함** | 안 함 | 안 함 |
| `true` | 내 링크 | 좌측 선택 | 안 함 | 안 함 |
| `true` | 조직 전체 | 우측 선택 | 렌더 | 렌더 + `나` 칩 |

- **member 에게는 스코프 토글을 아예 렌더하지 않습니다.** 잠긴 토글도 아닙니다 — 없습니다. 백엔드가 자기 발급분만 반환하므로 토글이 있어도 바뀔 게 없습니다.
- **스코프는 헤더, 상태는 툴바.** 세그먼트를 한 줄에 둘 쌓지 마세요.
- **"내 링크" 스코프에서는 발급자 아바타도 발급자 필터도 없습니다.** 조직 전체일 때만 나타납니다.
- **발급자는 열이 아니라 메타 라인입니다.** 열로 빼면 산출물 열이 634 → 493 으로 줄어 제목이 상시 잘립니다(`GEOMETRY.md §B2`). 아바타는 **16px 고정** — 18px 로 키우면 행 높이가 1px 늘어 11행 기준이 깨집니다.
- **남의 링크 철회 시에만** 확인 모달 맨 위에 소유자 경고 밴드가 붙습니다(`§1.11`). 모달을 둘로 나누지 말고 밴드 하나를 조건부로 끼우세요.
- **남의 링크에도 액션 3종은 전부 활성입니다.** `issuer.isMine` 은 잠금에 영향을 주지 않습니다 — 백엔드 RLS(`update_owner_or_admin`)가 admin 철회를 허용하므로 프런트에서 막으면 정책이 어긋납니다.
- **멤버 관리는 이 번들에 없습니다** — 브리프 §9 (b) 대로 기존 `/members` 소관입니다.

### 3-4. 철회 = 비가역
- 확인 모달은 필수이고, **영향 범위를 숫자로 말합니다**("초대받은 4명 모두 열 수 없습니다" + 이메일 칩).
- **확정 버튼 라벨은 "링크 끄기"** — "확인"이 아닙니다.
- **재발급 시 주소가 바뀌어 이미 보낸 메일의 링크는 살아나지 않는다**는 문장을 빼지 마세요. 이걸 모르고 끄는 게 가장 비싼 실수입니다.

### 3-5. 복사 · PII
- 복사 피드백은 **누른 버튼 자리에서** 일어납니다. **토스트를 쓰지 마세요** — 18행 목록에서 어느 행을 복사했는지 말해주지 못합니다.
- 복사 버튼은 `min-width: 82px` — 라벨이 늘어도 액션 열이 튀지 않게.
- 클립보드 실패 시 **주소를 직접 선택할 수 있게** 노출합니다.
- **이메일 표기:** 목록 행은 `로컬파트@…` 로 마스킹, **펼침 팝오버에서만 풀 주소**. `recruiting-scheduling.dc.html` 선례와 동일합니다.

### 3-6. 아이콘
UI 컨트롤에 **이모지를 쓰지 않습니다**. 전부 `iconography-duotone/` 인라인 SVG (매핑 = `BUILD-SPEC §1.10`).
> 이 표면만의 규칙: **행 타일은 배경이 파스텔이므로 아이콘 채움이 `paper`(흰색)입니다.** 34px 타일 안 18px 아이콘에 듀오톤 파스텔을 또 쓰면 형태가 뭉칩니다. 다른 번들의 "아이콘은 놓인 위젯 톤으로 채운다" 규칙과 다른 이유가 이것입니다.
