# Handoff: 위젯 체인 UI v2 — 커넥터 오버레이 (방향 ②)

## Overview
캔버스의 위젯 카드들을 **카드 사이의 엣지**로 잇는 체인 UI입니다. 파일럿 체인은 프로빙 → 전사 → 인터뷰 분석 → 탑라인 4단계이고, 모드는 2가지입니다(단계별 승인이 기본, 자동은 사용자가 켤 때만). v1(상단 체인 바 + 위젯 안 토글)을 대체합니다. **v1에서 만든 백엔드·`ChainView` 계약·칩·i18n은 그대로 쓰고, 바꾸는 것은 화면 표현뿐입니다.**

- 인풋 브리프: 레포의 `design-handoff/widget-chain/CONTEXT-FOR-CD-V2.md`(v2 의뢰), `CONTEXT-FOR-CD.md` §3 (`ChainView`), `WRITER-ANSWERS.md`
- 사용자는 브리프의 3방향 중 **② 커넥터 오버레이**를 골랐습니다. 비교 컴프 단계는 건너뛰었습니다.
- PR #1329(v1 구현)의 프레젠테이션 컴포넌트(`ChainBar`, `ChainEntryBlock`)는 이 문서 기준으로 교체합니다. `ChainChip`은 그대로 씁니다.

## About the Design Files
이 폴더의 `widget-chain-v2.dc.html`은 **HTML로 만든 디자인 레퍼런스**입니다. 의도한 생김새와 동작을 보여주는 프로토타입이며, 그대로 복사해 쓰는 프로덕션 코드가 아닙니다. 작업은 이 디자인을 **airesearcher 레포의 기존 환경(Next.js + React + Tailwind, `globals.css` 토큰)** 안에서 기존 패턴과 라이브러리로 다시 구현하는 것입니다. 파일을 브라우저로 열 때는 같은 폴더의 `support.js`가 필요합니다. `support.js`는 컴프를 띄우는 런타임일 뿐이라 옮길 대상이 아닙니다.

## Fidelity
**High-fidelity.** 색, 타이포, 간격, 상태 표현이 최종값입니다. 다만 카드 **본문**은 축소한 자리표시(회색 블록)이므로 각 위젯의 실제 본문을 그대로 쓰면 됩니다. 이 디자인에서 새로 만드는 것은 **엣지 · 포트 · 캡슐 · 산출물 노드 · 요약 pill · 진입 팝오버** 여섯 가지이고, 위젯 셸(헤더·툴바)은 바꾸지 않습니다.

## 핵심 규칙 (먼저 읽기)
1. **엣지는 거터로만 지나갑니다.** 카드 상단에서 50px 위의 가로선(거터 레인)을 따라가며, 카드를 가로지르지 않습니다. 체인 카드 사이에 다른 카드(라이브 통역)가 있어도 그 위로 넘어갑니다.
2. **상태는 엣지가 보여줍니다.** 진행 중 = 보라색 흐름 애니메이션, 승인 대기 = amber 점선, 멈춤 = **들어가는** 엣지가 끊기고 Ⅱ, 실패 = **나가는** 엣지가 끊기고 ✕, 완료 = 검정 실선.
3. **결정은 캡슐에서 합니다.** 승인, 충전, 실패 안내는 해당 엣지 가운데 위에 붙는 캡슐 하나로 처리합니다. 모달과 토스트는 쓰지 않습니다.
4. **진입은 출력 포트에서 합니다.** v1의 위젯 안 토글 블록을 없애고, 카드의 출력 포트를 누르면 팝오버가 열리는 방식으로 바꿉니다. 드래그로 잇는 방식은 쓰지 않습니다.
5. **상단 바는 요약 pill로 줄입니다.** 캔버스 좌상단에 놓고, 누르면 캔버스가 체인 쪽으로 이동합니다. 비체인 카드를 흐리게 하는 것은 체인에 포커스가 있을 때만입니다.

## Screens / Views
모든 장면은 캔버스 한 구간(컴프 프레임 1660×636)입니다. 실제 캔버스에서는 카드 위치를 DOM에서 측정해서 엣지를 그립니다(아래 *Geometry* 참조).

### S0 — 진입: 출력 포트에서 체인 만들기
- **트리거:** 체인을 지원하는 위젯(파일럿에서는 프로빙)의 카드에 hover나 포커스가 가면 **출력 포트 핸들**이 나타납니다. 위치는 카드 상단 테두리 위, 오른쪽 끝에서 56px 안쪽입니다.
- **핸들:** 26×26 원 · bg `#1d1b20` · border 2px `#1d1b20` · 글리프 `+` 13/800 흰색 · 링 `0 0 0 4px #fff, 0 0 0 6px #ff5c8a`.
- **팝오버:** 372px · border 2px ink · radius 12 · shadow `4px 4px 0 rgba(29,27,32,.2)` · 핸들 오른쪽 아래(왼쪽 +24, 거터 안)에 열립니다. 내용:
  - 제목 "세션이 끝나면 이어서 진행" 14/800 · 부제 "프로빙의 산출물을 다음 위젯으로 넘깁니다" 11.5 `#5b5965`
  - 세그먼트 [단계별 승인 | 자동]: border 1.5 ink · radius 10 · 선택된 쪽 ink 채움 + 흰 글자 · 셀 pad 6/14 · 12/800. 기본값은 단계별 승인입니다.
  - 미리보기 표(border 1.5 `rgba(29,27,32,.14)` · radius 10). 행: 번호(mono 10 `#8a8693`) · 톤 도트 11 · 이름 12/700 · 노트 10.5 · 비용(mono 11/800, 우측 정렬, 폭 52).
    - `2 · 전사 · 완료 시 · 💎1` / `3 · 인터뷰 분석 · 파일당 · 💎25` / `4 · 탑라인 보고서 · 포함`
    - 합계 행 bg `#f7f7f5`: "세션 후 이어질 비용" — **💎1 + 파일당 25**. 파일 수는 세션이 끝나야 정해지므로 추정 금액을 넣지 않습니다.
  - 자동을 고르면 amber 경고 박스("단계마다 묻지 않고 크레딧이 차감됩니다. 잔액이 모자라면 그 단계에서 멈춥니다.")가 추가됩니다. 내용은 v1과 같습니다.
  - 푸터 bg `#fbfbf9` · border-t 1.5: "취소" 텍스트 · [연결하기] ink pill.
- **팝오버가 열려 있는 동안:** 이어질 경로를 **고스트 엣지**(`rgba(29,27,32,.32)`, 2px, dash `6 6`)로 미리 보여주고, 받는 쪽 입력 포트를 강조합니다(16 원 · border 2px **dashed** ink · ring `0 0 0 3px rgba(255,92,138,.25)`). 연결하기를 누르면 체인이 생기고 S1 형태가 됩니다.

### S1 — 진행 중
- 진행 중인 단계로 **들어가는 엣지 하나**만 running입니다. 바탕 path `#d6c7f5` 3px 위에 흐름 path `#8b5cf6` 3px · dash `10 14` · `stroke-dashoffset` 0 → −48 · 1.1s linear 무한 반복.
- 엣지 가운데에 **상태 라벨** pill이 붙습니다: bg `#f6f2ff` · border 1.5 `#d6c7f5` · 11/800 `#6b4aa0` · pad 3/11. 문구는 `{현재 단계} 중 · {n}/4`.
- 나머지 엣지는 pending(`#c9ccd2`, 2px, dash `5 6`)입니다.
- 카드 칩(v1 `ChainChip`, 서브바 우측)은 v1 그대로입니다.

### S2 — 승인 대기 (핵심)
- 대기 중인 엣지는 amber 점선(`#e0a83a`, 2.5px, dash `7 6`)입니다.
- **캡슐**은 엣지 가운데 바로 위에 붙습니다. 폭 400 · border 2px `#e0a83a` · radius 12 · bg `#fff` · shadow `4px 4px 0 rgba(29,27,32,.2)`. 캡슐 아래에 2×12 세로선(`#e0a83a`)이 있어 엣지와 이어집니다. **캡슐은 아래쪽(엣지에 붙는 쪽)을 기준으로 고정**하고 내용이 늘면 위로 자랍니다.
  - 윗줄: 도트 8 amber · eyebrow mono 10/800 .1em 대문자 `#8a5a10` "다음 · 인터뷰 분석" · 우측 비용 mono 11/800 "💎25"
  - 메시지 12.5/1.55 `#2a262f`: "전사가 끝났습니다. **시작하면 바로 차감**됩니다." (굵게 한 구간 = `#1d1b20`)
  - 액션 행: border-t 1.5 `#f0d78a` · bg `#fff1e6` · pad 8/13. 왼쪽 "체인 종료"(11.5/700 `#5b5965` 텍스트 버튼), 오른쪽 [건너뛰기](paper pill, border 1.5 ink, 12/700)와 [**진행 · 💎25 →**](ink pill, border 2, 12.5/800, shadow `2px 2px 0 rgba(29,27,32,.28)`)
- 받는 카드의 본문은 잠그지 않습니다. 칩만 "승인 대기"(amber)로 바뀝니다.
- 진행 버튼 문구는 `진행 · 💎{steps[i+1].cost} →`이고, cost가 0이면 `진행 →`입니다.

### S2b — 승인 대기 · 프로젝트가 필요할 때
- `projectId === null`이고 다음 단계가 `interview_ingest`이면 캡슐 안 메시지 아래에 **프로젝트 피커**를 넣습니다(border 1.5 ink · radius 10 · shadow `2px 2px 0 #1d1b20` · placeholder "대상 프로젝트 선택" 12/700 `#8a8693`). 피커 패널은 기존 Picker 시스템(포털 z-60)을 쓰고, 첫 항목은 "+ 새 프로젝트"입니다.
- 프로젝트를 고르기 전까지 진행 버튼은 **잠금 상태**입니다: bg `#eceef1` · 글자 `#8a8693` · border `rgba(29,27,32,.2)` · 그림자 없음. 건너뛰기는 **숨깁니다**.

### S3 — 비체인 카드 공존
- 체인에 묶이지 않은 카드(라이브 통역)는 **아무것도 바뀌지 않습니다.** 흐리게 하지 않고 포트도 보이지 않습니다. 사용자는 체인이 도는 동안에도 이 카드를 평소대로 씁니다.
- 체인 엣지는 거터 레인으로 그 카드 위를 넘어갑니다.

### S3b — 체인 포커스
- 엣지, 캡슐, 요약 pill, 체인 칩 중 하나에 hover나 키보드 포커스가 가면 **비체인 카드를 `opacity: .32`**로 흐립니다. 들어갈 때와 나올 때 모두 150ms ease-out입니다. 체인 카드, 엣지, 캡슐은 그대로 둡니다.
- **요약 pill**(캔버스 좌상단 18/20 고정, 캔버스를 스크롤해도 화면에 남음): border 1.5 ink · radius 999 · pad 5/12/5/6 · shadow `2px 2px 0 rgba(29,27,32,.14)`. 구성은 [22 원 타일 + 링크 아이콘] "체인"(12/800) · 모드(10.5/700 `#5b5965`) · 구분선 1.5×13 · 상태 텍스트(mono 11/800, 상태 색). 자동 모드일 때는 타일을 ink로 채우고 아이콘을 흰색으로 바꿉니다. 클릭하면 캔버스를 체인 경계로 스크롤하고 포커스 상태로 들어갑니다. **pill에는 승인 버튼을 두지 않습니다.**

### S4 — 크레딧 부족으로 멈춤 (`paused_insufficient_credits`)
- 멈춘 단계로 **들어가는 엣지**를 가운데에서 끊습니다. 앞쪽 반은 amber 실선 2.5, 뒤쪽 반은 pending 점선이고, 끊긴 자리에 **Ⅱ 마크**를 둡니다(26 원 · border 2 `#e0a83a` · bg `#fff` · 12/800 `#8a5a10`).
- 캡슐(amber): eyebrow "멈춤 · 인터뷰 분석" · 비용 "필요 💎25" · 메시지 "잔액 💎12 — **💎25**가 필요해 여기서 멈췄습니다." · 액션은 체인 종료(텍스트) / [재개] / [💎 충전하기](주 버튼).
- 자동 모드도 여기서 멈춥니다. **보라색, 흐름 애니메이션, 링은 하나도 남기지 않습니다**(유령 상태 금지).

### S5 — 단계 실패 (`error`)
- 실패한 단계에서 **나가는 엣지**를 끊습니다. 앞쪽 반은 `#ef4444` 실선, 뒤쪽 반은 pending이고, 끊긴 자리에 ✕ 마크(26 원 · border 2 `#ef4444` · bg `#fdf0f0` · `#b4443f`)를 둡니다.
- 엣지 위치로 구분합니다: **멈춤 = 들어가는 엣지 / 실패 = 나가는 엣지.**
- 캡슐(error): border `#ef4444` · 액션 행 bg `#fdf0f0` · line `#f0c0c0`. eyebrow "체인 종료됨 · 인터뷰 분석 실패" · 메시지 **`{steps[i].error}`** + ". 이 위젯에서 다시 시도하세요." · 액션은 [닫기] / [인터뷰 결과 열기].
- 재시도 버튼은 두지 않습니다(실패하면 체인이 끝납니다). 크레딧 환불 문구는 정책이 확인될 때까지 넣지 않습니다.

### S6 — 완료 (`done`)
- 모든 엣지가 검정 실선 2.5가 됩니다. 마지막 엣지는 **산출물 노드**로 들어갑니다.
- **산출물 노드** "탑라인 보고서": 200×150 · 마지막 카드 오른쪽 64px · 카드와 상단을 맞춤. 체인이 있는 동안만 렌더합니다.
  - pending: border 1.5 dashed `#c9ccd2` · 헤더 흰색(1.5 dashed 하단선) · 빈 점선 타일 · "대기" `#a3a7ad`
  - done: border 2.5 ink · shadow `4px 4px 0 rgba(29,27,32,.24)` · 헤더 bg `#ffd0e2`(2px 하단선) · 타일 34 bg `#f4fbf6` · shadow `3px 3px 0 #16a34a` · ✓ `#16a34a` · "준비됨" `#14713a`
  - 인터뷰 분석과 탑라인은 같은 위젯이 맡으므로, 인터뷰 카드 칩은 `체인 3–4/4`로 표시합니다.
- 캡슐(success): border `#16a34a` · 액션 행 `#f4fbf6`/`#cdeed8`. eyebrow "4/4 완료" · 메시지 "**탑라인 보고서가 준비됐습니다.** 인터뷰 결과 전체보기에서 엽니다." · 액션은 [닫기] / [보고서 열기 ⤢]. 보고서 열기를 누르면 인터뷰 결과 생성기 풀뷰가 보고서 탭으로 열립니다.
- 완료 캡슐은 **자동으로 사라지지 않습니다.** 닫기를 누르면 캡슐, 엣지, 포트, 산출물 노드, 칩, 요약 pill이 모두 사라집니다.

### S7 — 종료 (`cancelled`)
- 끝까지 간 엣지는 검정 실선으로 남고, 가지 못한 엣지는 pending 회색 점선이 됩니다. 남은 포트는 dim(14 원 · 1.5 dashed `#c9ccd2`)으로 바꿉니다.
- 캡슐(neutral): border ink · 도트 `#8a8693` · 액션 행 `#f7f7f5`. 메시지 "체인을 종료했습니다. **전사까지의 결과**는 각 위젯에 그대로 있습니다." · 주 버튼은 [닫기] 하나뿐입니다.
- 색이 있는 요소는 없습니다(공유 링크 dead end와 같은 규칙).

## Geometry
컴프 값이며, 실제 구현에서는 측정한 카드 rect로 계산합니다.
- 포트: **출력 = 카드 상단 테두리 · 오른쪽 끝에서 56px 안쪽**, **입력 = 카드 상단 테두리 · 왼쪽 끝에서 56px 안쪽**. 원 16 · border 2px ink. 출력 포트는 그 위젯 톤으로 채우고, 입력 포트는 흰색입니다. **포트는 체인에 묶인 카드에만 렌더합니다.**
- 거터 레인 y = `카드 top − 50`. 엣지 경로는 출력 포트에서 위로 올라가 레인을 따라 가로로 간 뒤 입력 포트로 내려옵니다. 모서리는 2차 곡선 r=14입니다.
  ```
  M x1 (top-8)  V lane+14  Q x1 lane, x1+14 lane  H x2-14  Q x2 lane, x2 lane+14  V (top-15)
  ```
  끝에 화살촉 삼각형(밑변 12, 높이 8, 꼭짓점 top−9)을 붙이고 색은 엣지 색과 같습니다.
- 끊긴 엣지(멈춤/실패): 레인 가운데 ±17px를 비우고 앞쪽 반과 뒤쪽 반을 따로 그립니다. 화살촉은 뒤쪽 반 색(pending)을 씁니다.
- 캡슐: 가로는 엣지의 가로 구간 중앙에 맞추고, 아래쪽 끝은 `lane − 12`(그 아래 12px 세로선이 엣지에 닿음)에 둡니다.
- 상태 라벨: 엣지 중앙, 레인 위에 걸치게 둡니다(y center = lane).
- 레이어 순서(z): 카드 2 · 엣지 SVG 3(`pointer-events: none`) · 포트 4 · 라벨/마크 5 · 캡슐 6 · 요약 pill 7 · 진입 팝오버 8 · Picker 패널 60(포털).
- **거터 확보:** 체인이 활성화되면 체인 카드가 놓인 행 위쪽에 최소 **186px**(캡슐 높이 + 레인)의 빈 공간이 있어야 합니다. 캔버스 첫 행이면 캔버스 top padding을 체인이 있는 동안 늘립니다. ⚠️ 체인 카드가 **서로 다른 행**에 있는 경우는 그리지 않았습니다 — 아래 *열린 항목* 참조.

## Interactions & Behavior
- 액션 `approve(i)` · `skip(i)` · `cancel()` · `resume()`는 컨테이너(v1 그대로)가 담당하고, 프레젠테이션 컴포넌트는 콜백만 받습니다.
- 체인 종료에는 확인 모달이 **없습니다**(데이터가 지워지지 않고, 종료 캡슐 문구가 그 사실을 알려줍니다).
- 완료·실패·종료 캡슐은 닫기를 눌러야만 사라집니다.
- 카드를 드래그해 옮기거나 캔버스를 리사이즈하면 엣지와 캡슐이 따라가야 합니다(`ResizeObserver` + 카드 rect 다시 측정, rAF로 묶어서 처리).
- 캔버스 줌이 있다면 엣지 SVG는 카드와 같은 transform 레이어 안에 둡니다(화면 좌표계가 아님).
- `prefers-reduced-motion: reduce`이면 흐름 애니메이션을 끄고 running 엣지는 정적 보라 실선 3px로 그립니다.
- 키보드: 출력 포트 핸들, 캡슐 버튼, 요약 pill은 Tab으로 접근할 수 있어야 합니다. 포트 핸들 aria-label은 "이어서 진행할 위젯 연결"입니다. 포커스 링은 제품 공통 focus-ring을 씁니다(아직 미승격이면 `0 0 0 2px #fff, 0 0 0 4px #1d1b20`).

## State Management
- 원천 데이터: `ChainView`(v1 계약, 변경 없음) — `status`, `mode`, `currentStep`, `steps[] {feature, status, cost, error?}`, `projectId`.
- 프레젠테이션에서 파생하는 값:
  - 엣지 i의 종류: `steps[i]`와 `steps[i+1]` status 조합으로 정합니다 — 앞 done + 뒤 running → `running` / 뒤 awaiting → `awaiting` / chain.status가 paused이고 i+1 == currentStep → `paused` / 앞 error → `error`(나가는 엣지) / 둘 다 done → `done` / 그 외 → `pending`. cancelled이면 done이 아닌 엣지는 전부 `pending`.
  - 캡슐 위치: awaiting·paused는 currentStep으로 **들어가는** 엣지, error는 실패 단계에서 **나가는** 엣지, done은 마지막 엣지, cancelled는 마지막 done 다음 엣지.
  - `feature → 카드 DOM` 매핑: 같은 위젯이 두 단계를 맡으면(interview_ingest + topline) 카드는 하나이고, 마지막 엣지는 산출물 노드로 갑니다.
- 로컬 UI 상태: `entryPopoverOpen`, `chainFocused`(hover/focus → 비체인 카드 dim), `dismissed`(종료 상태 캡슐을 닫았는지).

## 열린 항목 (writer / 워커 확인)
1. **카드가 서로 다른 행에 있을 때 엣지 경로** — 그리지 않았습니다. 제안: 출발 카드 위 레인 → 카드 사이 세로 거터 → 도착 카드 위 레인. 파일럿 4위젯이 같은 행에 놓이는지 먼저 확인해 주세요.
2. **사용자가 수동으로 배치한 카드와 거터 확보가 충돌할 때** — 체인 활성 중에는 해당 행 위 186px를 비우는 것으로 가정했습니다. 캔버스 레이아웃 엔진에서 가능한지 확인이 필요합니다.
3. v1 BUILD-SPEC §5의 계약 질의(파일 수, 크레딧 잔액, 실패 시 환불, 종료 시 남은 단계 status, 프로젝트 목록 소스)는 그대로 유효합니다. S4의 "잔액 💎12"는 `creditBalance`가 없으면 빼고, 빼도 레이아웃은 그대로입니다.
4. 4개 로케일 카피: 한국어만 그렸습니다. 메시지는 `msgA / **msgB** / msgC` 세 조각 구조입니다.
