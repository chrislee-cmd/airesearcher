# 공유 관리 대시보드 — CD 아웃바운드 핸드오프 (writer → CD, 2026-08-06)

## 0. 한 줄 요약

발급한 **공유 링크 전체를 한눈에 보고 관리하는 화면**을 새로 디자인해 주세요. 링크 "발급"은 이미 각 위젯 풀뷰의 공유 모달로 동작합니다 — 이번 범위는 **조망 + 관리(철회/복사/초대 편집 진입)** 뷰 하나입니다.

## 1. 배경 (현재 동작하는 것 — 재디자인 대상 아님)

- 공유 가능한 산출물 6종: 인터뷰 탑라인 · 프로빙 페르소나 · 전사록 · UT 인사이트 · 데스크 리포트 · 리크루팅 집계. 각 풀뷰에 공유 버튼 → 공유 모달(링크 생성, 이메일 초대 allow-list 추가/제거, 철회, 복사)이 이미 있음.
- 공개 뷰어(`/share/…`)는 이메일 게이트(OTP)로 열림. 만료 기본 30일.
- **없는 것**: 내가(또는 우리 조직이) 지금까지 발급한 링크들을 흩어진 풀뷰 밖에서 한꺼번에 보는 표면. "어느 링크가 살아있지? 이거 아직도 열리나? 끄고 싶다" 를 지금은 각 산출물을 일일이 찾아 들어가야 함.

## 2. 짓는 것 (범위)

**"공유 관리" 대시보드 — 프레젠테이션 레이어** (데이터 페칭 없음, typed props):

- 발급 링크 목록. 항목당: 산출물 종류(6종 구분) · 산출물 제목 · 링크 상태 · 만료일 · 초대된 이메일들 · 생성일.
- 항목 액션: **링크 복사** · **철회(revoke, 확인 단계 포함 — 비가역)** · **초대 편집 열기**(기존 공유 모달 호출 — 모달 자체는 재디자인 범위 아님).
- 정렬/그룹은 CD 판단(예: 상태별, 산출물 종류별, 최신순).

## 3. 데이터 계약 (컨테이너=워커가 주입 — 이 shape 은 확정)

```ts
type ShareLinkItem = {
  id: string;
  resourceType: 'interview_topline' | 'probing_persona' | 'transcript'
              | 'ut_insight' | 'desk_report' | 'recruiting_summary';
  resourceTitle: string;        // 산출물 제목 (백엔드 보강 예정 — 계약 확정)
  url: string;                  // 복사 대상 전체 URL
  status: 'active' | 'expired' | 'revoked';
  createdAt: string;            // ISO
  expiresAt: string | null;     // ISO, null = 무기한 없음(항상 존재 예정이나 방어)
  invitedEmails: string[];      // 0..N
  viewCount?: number | null;    // §5 참조 — 렌더 여부 CD 결정
};

// 액션 (프레젠테이션은 호출만):
onCopy(item), onRevoke(item), onOpenInviteManage(item)
```

## 4. 상태 전수 (전부 그려야 함)

1. **빈 상태** — 발급 링크 0건 (첫 사용자).
2. **목록** — active / expired / revoked 혼재 시 구분이 한눈에.
3. **철회 확인** — 비가역 액션. 확인 단계 필수.
4. **복사 피드백**.
5. **로딩 skeleton**.
6. expired/revoked 항목의 처리(흐림? 별도 그룹? 숨김 토글?) — CD 판단.

## 5. 열람수(viewCount) 관련

- 열람 수집 백엔드는 병행 준비 중(집계 count + 최종 열람 시각 제공 가능, **개별 열람자 신원은 미제공** — PII 최소화 확정).
- 선례: 인터뷰 공유 모달에서는 "연 사람 N명" **미렌더** 결정(DECISIONS #4). 대시보드에서 보여줄지는 **신규 결정 — CD 제안 → 사용자 확정** 절차로.

## 6. 자리(셸) 권고

- 다른 자리가 더 낫다고 보면 역제안 환영 (단, 프로필/설정 깊숙이 묻는 배치는 비권장 — 협업 기능의 발견성이 목적).

## 7. 제약

- 이메일 주소 = PII — 표시 방식(풀 표기/마스킹)은 기존 공유 모달과 일관되게.
- 기존 CD-DELIVERABLE-RULES 동일 적용(토큰만·임의 hex 0·이모지 금지 등). 산출물 = 표준 번들(README + HANDOFF + BUILD-SPEC + .dc.html, 상태 전수 프레임).
- 기존 공유 모달·풀뷰 버튼은 무변경 — 이 화면에서 호출만 합니다.
