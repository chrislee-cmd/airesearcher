# 캔버스 모듈화 — 팔레트 + 작업면 재설계 의뢰 (writer → CD)

_2026-10-10 · writer · 신규 에픽 (체인 파일럿의 다음 단계 — 캔버스 패러다임 전환)_

## 0. 배경 — 왜 그리드가 어색해졌나 (사용자 피드백 원문)

> "이 구조는 기존의 그리드 스타일 캔버스가 아니라, **위젯 하나하나가 단순히 추가를 위한 모듈**이 되어야 하고, 그것에 최적화된 UX 가 잡혀야 할 것 같아. 지금의 자유 네비게이션 형태의 캔버스에서 굳이 3×3 그리드 형태는 최적이 아니라는 것은 맞는 것 같아."

체인 도킹 레인(widget-chain v3, PR #1329)이 들어오면서 위젯의 정체성이 이동했습니다: **"진열된 독립 작업 화면" → "조립에 쓰는 모듈"**. 9장의 실물 카드(604×900)를 상시 진열하는 3×3 그리드는 이전 정체성의 유물이고, 레인이 1급 시민이 된 캔버스에서는 진열대가 아니라 **공급원(팔레트)과 작업면**이 필요합니다.

## 1. 확정 방향 — **방향 1: 팔레트 + 작업면** (writer 권장 → 사용자 전송 지시)

- **팔레트**: 위젯은 **컴팩트 모듈 타일**(이름·아이콘·크레딧·톤 — 실카드 아님)로 공급원에 산다. 기존 위젯 메타(labelKey·accent·cost) 재사용.
- **작업면**: 자유 네비게이션 공간. **사용 중인 것만 존재** — 체인 레인(v3 그대로 승계)과, Phase 2 에선 단독 실행 위젯 인스턴스. 빈 작업면이 기본 상태.
- **동작**: 팔레트에서 끌어온다 — 레인(또는 빈 레인 슬롯)에 놓으면 체인 단계, (Phase 2) 빈 작업면에 놓으면 단독 카드 인스턴스.
- 3×3 그리드·상시 카드 진열은 퇴역.

참고로 기각/보류된 대안(맥락용): 방향 2 "모든 것이 레인"(단독 위젯 = 길이 1 레인 — 개념 통일은 좋으나 단독 사용에 과한 껍데기) · 방향 3 점진 개선(그리드 유지 + 컴팩트 카드 — 근본 진단 미해소). CD 가 방향 1 설계 중에 2 의 요소를 차용할 가치가 보이면 소견으로.

## 2. 이번 의뢰 범위 — ⚠️ 풀 번들 아님, **멘탈 모델 확정 장면부터**

체인에서 두 번(v1·v2) 배운 절차입니다: 큰 패러다임 전환은 사용자가 핵심 장면을 눈으로 확정한 뒤 풀 번들로 갑니다. **장면 4컷 내외의 목업**을 요청합니다:

| # | 장면 | 확정하려는 것 |
|---|---|---|
| M0 | 기본 화면 — 팔레트 + 빈 작업면 (+레인 하나 있는 변형) | 팔레트의 위치·형태(독/사이드바/하단?), 모듈 타일 문법, "빈 캔버스" 의 첫인상 |
| M1 | 팔레트 → 레인 드래그 | 모듈 타일이 레인 슬롯으로 들어가는 동작 — v3 도킹 문법과의 접속 |
| M2 | 작업면에 레인 + (Phase 2 미리보기) 단독 인스턴스 1장 공존 | 레인과 단독 카드가 한 공간에 사는 모습 |
| M3 | 팔레트 상태 표현 | 실행 중/체인 소속/비활성(체인 미지원) 위젯이 팔레트에서 어떻게 구분되는가 |

각 장면에 결정 메모(선택지와 기각 사유) — v3 번들의 "CD 결정" 표 형식이 좋았습니다.

## 3. 불변 조건

- **체인 레인 v3 전부 승계** — 레인·슬롯·세그먼트·캡슐·산출물 노드·툴바 pill 은 작업면의 1급 주민으로 그대로. 레인 내부는 재설계 대상 아님.
- 위젯 셸(604×900 카드) — 레인 안·(Phase 2) 단독 인스턴스에서 실치수 유지. 팔레트 타일은 **신규 문법**(셸 아님).
- `ChainView` 계약·모드·크레딧 고지 불변. 호환 가드(드롭 가능 판정)는 기존 `CHAIN_COMPAT_EDGES` SSOT.
- 토큰: 기존 tokens 2.0, 신규 토큰은 proposed-token 으로.

## 4. CD 열린 질문 (설계 중 답해 주시면 좋은 것)

1. **발행 배치/visibility 시스템의 거취** — 그리드 좌표가 퇴역하면 어드민 발행은 "팔레트 노출·순서" 로 전환되는가.
2. **Navigator(작업 상태 패널)의 거취** — 팔레트가 상태 표현(M3)을 갖게 되면 중복인가 통합인가.
3. Phase 1(팔레트+작업면+레인)과 Phase 2(단독 인스턴스) 사이에서 **단독 실행의 과도기 UX** — Phase 1 에서 단독 사용자는 어디서 위젯을 여는가 (팔레트 타일 클릭 = 풀뷰 직행?).
4. 모바일/좁은 뷰포트의 팔레트.
