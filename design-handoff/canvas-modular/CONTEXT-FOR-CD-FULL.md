## 0. 확정 사실

사용자가 M0~M3 를 검토하고 **확정**했습니다 (2026-10-12). 장면의 결정 전부 — 팔레트 좌측 레일 240 · 타일 216×64 · 제스처 단일 의미(끌기=조립·누르기=이동/열기) · 타일 고스트 드래그 · 공급원 불변 · 미지원 비흐림 · Navigator 퇴역 · 발행=노출+순서 — 재론 없이 풀 번들의 전제입니다. writer 회신(`scenes/WRITER-ANSWERS-SCENES.md`)도 반영 전제: 로스터 = 발행 SSOT(9종 — 가이드라인 생성기·영상 분석기 포함, 같은 타일 문법), Navigator 퇴역 확정(코드 검증 완료), proposed-token 2건 접수.

## 1. 의뢰 범위 — **Phase 1 풀 번들** (v2/v3 수준: README + .dc.html, 필요시 BUILD-SPEC)

Phase 1 = **팔레트 + 작업면 + 레인(v3 승계)**. 단독 인스턴스(Phase 2)는 범위 밖 — M2 미리보기 수준으로 동결.

풀 번들이 채워야 할 것 (장면에서 안 그려진 부분):
1. **팔레트 전 상태 실치수 스펙** — M3 의 9종을 v3 README 수준의 수치 표(테두리·그림자·색·타이포·전이 조건)로. 접힌 레일 72 포함. 9종 로스터 전체(신규 2종 아이콘 포함 — duotone 세트).
2. **팔레트 타일 작업 목록 펼침** (Navigator 흡수분) — 타일에서 "같은 위젯의 여러 실행 이력"을 펼치는 상호작용. Navigator 가 하던 포커스 이동 기능 승계.
3. **드래그 전 구간** — 타일 픽업(포인터/키보드) → 레인 위 피드백(v3 L1/L2/L2b 접속) → 드롭 교체 모션(160ms 페이드) → 취소 복귀. 두 좌표계(화면 고정 팔레트 ↔ 캔버스 transform) 횡단 명시.
4. **그리드 퇴역의 잔여 화면** — 레인이 없고 아무것도 실행 중이 아닐 때(M0a), 레인만 있을 때(M0b), 레인 밖 실행 위젯이 있을 때(풀뷰에서 돌고 있는 경우 팔레트 표시만인지).
5. **Done-when** — v3 형식.

## 2. 열린 질문 2건 (사용자 확정 시 writer 가 짚은 것 — 번들에서 답할 것)

1. **전환 온보딩**: 기존 그리드 사용자가 첫 진입에서 "위젯이 사라졌다"고 느끼는 충격 완화 — 1회성 안내(코치마크/빈 상태 확장 등) 장면 1개. 과하지 않게(한 번 보고 끝).
2. **복수 실행 중첩**: Phase 1 에서도 같은 위젯이 "레인 소속 + 풀뷰 단독 실행" 으로 동시에 일을 가질 수 있음 — 타일 둘째 줄이 어느 것을 보여주고, "누르면 어디로" 가 어떻게 갈리는지 (2 의 작업 목록 펼침과 연결 가능).
