## 질의 ① — 팔레트 머리 vs 앱 Topbar 의 중복 (결정 위임)

컴프(§4.1)는 팔레트 머리에 **로고·워드마크 + 사용자 줄**을 그렸습니다. 그런데 컴프 프레임(1280×800)에는 없는 **실제 앱 Topbar 가 이미 브랜드·사용자·크레딧을 소유**합니다. 머지 직후 상태 = **양쪽에 로고와 사용자 표시가 중복**.

**사용자가 해소 방향을 CD 에 위임했습니다.** 선택지 (다른 안도 환영):

- A. **팔레트 머리에서 브랜드·사용자 줄 제거** — 팔레트는 "위젯 모듈 서랍"으로 순수화, 앱 chrome 은 Topbar 단독 소유. (writer 관찰: 리브랜드 취지가 "정신없음 제거"라 중복 제거와 결이 같고, 변경 파일이 팔레트 쪽 1곳이라 쌈)
- B. **Topbar 축소/퇴역, 팔레트가 앱 chrome 흡수** — 컴프의 1280×800 구성을 문자 그대로 완성. (주의: Topbar 는 캔버스 밖 다른 라우트들도 쓰는 전역 chrome — 영향 범위가 캔버스 밖으로 넘침)
- C. 중복 유지 + 역할 분화 (예: 팔레트 쪽은 프로젝트 컨텍스트 표시로 전용)

답 형식: 선택 + 바뀌는 쪽의 장면 1장(또는 기존 .dc.html 수정)이면 충분합니다.

## 질의 ② — 줌 컨트롤 pill ("− 42% +")

컴프 12장면 전부에 그려져 있으나 §3 장면 목록·§11 Done-when 에 없고 현행 캔버스에 해당 컨트롤이 없습니다. 워커는 **미구현** (휠/핀치 줌은 기존대로). 

- 의도된 신규 컨트롤이면: 동작 정의가 필요합니다 — 스텝(몇 %씩), 범위(min/max), 위치 고정 기준(뷰포트 vs 작업면), reduced-motion, 그리고 "fit to content" 같은 리셋 동작 여부.
- 배경 연출이었다면: "Phase 2 불요" 한 줄이면 종료.
